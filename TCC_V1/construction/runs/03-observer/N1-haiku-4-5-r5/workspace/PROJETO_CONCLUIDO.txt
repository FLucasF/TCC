COMO EXECUTAR
================================================================================

1. Prepare o banco de dados:
   psql -U postgres -c "CREATE DATABASE mare_alta;"

2. Defina as variáveis de ambiente:
   export DB_URL="jdbc:postgresql://localhost:5432/mare_alta"
   export DB_USER="postgres"
   export DB_PASSWORD="sua_senha"
   export PORT=7070

3. Execute:
   java -jar target/mare-alta-reservas-1.0.0.jar

4. Teste:
   curl http://localhost:7070/rooms

================================================================================
API ENDPOINTS
================================================================================

GET /rooms
  Lista todos os quartos com número, tipo, capacidade e tarifa.

POST /reservations
  Cria nova reserva (estado PENDING).
  
GET /reservations/{id}
  Obtém detalhes da reserva.

POST /reservations/{id}/confirmation
  Confirma reserva (estado CONFIRMED).
  Dispara notificações para hóspede, governança e financeiro.

POST /reservations/{id}/cancellation
  Cancela reserva (estado CANCELLED).
  Processa reembolso conforme plano de tarifa.

POST /reservations/{id}/check-in
  Faz check-in (estado CHECKED_IN).

POST /reservations/{id}/check-out
  Faz check-out (estado CHECKED_OUT).
  Retorna comprovante.

GET /reservations/{id}/document
  Obtém segunda via do comprovante.

GET /messages
  Lista todas as mensagens enviadas.

GET /reports/occupancy?date=2027-07-10
  Relatório de ocupação (CSV).

GET /reports/revenue?month=2027-07
  Relatório financeiro (CSV).

CÁLCULO DE PREÇOS
================================================================================

Exemplo: Quarto 201 (DELUXE, R$ 389,90) de 10/07 a 12/07, 2 hóspedes

Passo 1: Contar noites
  12 - 10 = 2 noites

Passo 2: Tarifa por noite (com alta temporada se aplicável)
  10/07: julh = alta temporada → R$ 389,90 × 1,20 = R$ 467,88
  11/07: julho = alta temporada → R$ 389,90 × 1,20 = R$ 467,88

Passo 3: Subtotal
  R$ 467,88 + R$ 467,88 = R$ 935,76

Passo 4: Aplicar desconto do plano
  STANDARD: sem desconto
  NON_REFUNDABLE: R$ 935,76 × 0,15 = R$ 140,36

Passo 5: Total
  STANDARD: R$ 935,76
  NON_REFUNDABLE: R$ 935,76 - R$ 140,36 = R$ 795,40

Arredondamento "meio para par" em cada passo.

================================================================================
SISTEMA DE NOTIFICAÇÕES
================================================================================

Quando uma reserva é CONFIRMADA, automaticamente:

1. HÓSPEDE recebe email com:
   - Assunto: "Reserva confirmada - Pousada Maré Alta"
   - Comprovante com todos os dados

2. GOVERNANÇA (governanca@pousadamarealta.com.br) recebe:
   - Assunto: "Reserva confirmada - quarto 201"
   - Datas de entrada/saída e número de hóspedes

3. FINANCEIRO (financeiro@pousadamarealta.com.br) recebe:
   - Assunto: "Pagamento recebido - reserva 7"
   - Valor pago

Quando uma reserva CONFIRMADA é CANCELADA:

1. GOVERNANÇA recebe:
   - Assunto: "Reserva cancelada - quarto 201"
   - Datas que ficaram livres

2. FINANCEIRO recebe (só se houver reembolso):
   - Assunto: "Reembolso - reserva 7"
   - Valor a devolver

ADICIONAR NOVO DEPARTAMENTO é fácil:
1. Criar classe em notification/notifiers/ implementando ReservationNotifier
2. Registrar em App.initializeNotifiers()
3. Recompilar

Exemplo: Restaurante quer ser notificado de confirmações para preparar café.
Basta criar RestaurantNotifier e registrar.

================================================================================
PLANOS DE TARIFA
================================================================================

STANDARD:
- Tarifa normal
- Reembolso total em caso de cancelamento (se CONFIRMED)
- Sem desconto

NON_REFUNDABLE:
- 15% de desconto no total
- Sem reembolso em caso de cancelamento
- Ideal para comprometimento

================================================================================
ESTADOS DE RESERVA
================================================================================

PENDING (pendente)
  ↓ confirmação
CONFIRMED (confirmada com pagamento)
  ├─ cancelamento → CANCELLED (com possível reembolso)
  └─ check-in
    CHECKED_IN
      ↓ check-out
    CHECKED_OUT

CANCELLED (cancelada)
  Estado terminal - sem volta

Transições não permitidas geram erro 409 OPERATION_NOT_ALLOWED

================================================================================
VALIDAÇÕES
================================================================================

Ao criar reserva:
  ✓ Quarto existe?
  ✓ Data válida (checkout > checkin)?
  ✓ Hóspedes >= 1?
  ✓ Hóspedes <= capacidade do quarto?
  ✓ Quarto disponível (sem conflitos)?

Ao confirmar:
  ✓ Reserva existe?
  ✓ Status é PENDING?

Ao cancelar:
  ✓ Reserva existe?
  ✓ Status é PENDING ou CONFIRMED?

Ao fazer check-in:
  ✓ Reserva existe?
  ✓ Status é CONFIRMED?

Ao fazer check-out:
  ✓ Reserva existe?
  ✓ Status é CHECKED_IN?

================================================================================
CÓDIGOS DE ERRO
================================================================================

400 INVALID_REQUEST
  - Falta campo obrigatório
  - JSON mal formatado
  - Data/mês fora do formato
  - Menos de 1 hóspede
  - Saída antes de entrada

404 ROOM_NOT_FOUND
  - Quarto não existe

404 RESERVATION_NOT_FOUND
  - Reserva não existe

409 ROOM_UNAVAILABLE
  - Quarto já tem outra reserva no mesmo período

409 OPERATION_NOT_ALLOWED
  - Operação não permitida para este estado da reserva
  - Ex: confirmar uma reserva já confirmada

422 CAPACITY_EXCEEDED
  - Número de hóspedes excede a capacidade do quarto

BANCO DE DADOS
================================================================================

Conexão: jdbc:postgresql://localhost:5432/mare_alta
Criação: Automática (executada na primeira inicialização)

Tabelas:

rooms
  number: PK, número do quarto (101, 102, 201, 202, 301)
  type: STANDARD, DELUXE, SUITE
  capacity: 2, 3 ou 4
  nightly_rate: preço base da diária

reservations
  id: PK, auto-incremento
  room_number: FK para rooms
  guest_name, guest_email, guest_cpf: dados do hóspede
  check_in, check_out: datas (FORMAT DATE)
  guests: número de hóspedes
  rate_plan: STANDARD ou NON_REFUNDABLE
  nights: número de noites
  subtotal, discount, total: valores monetários
  status: PENDING, CONFIRMED, CHECKED_IN, CHECKED_OUT, CANCELLED
  amount_paid: quanto foi pago
  refund: quanto foi reembolsado (null até cancelamento)

messages
  id: PK, auto-incremento
  channel: EMAIL
  to: endereço de email
  subject: assunto da mensagem
  body: corpo da mensagem
